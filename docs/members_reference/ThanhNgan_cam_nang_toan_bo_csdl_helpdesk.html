⚡ Bản Đồ Các Loại Câu Lệnh SQL Trong Hệ Thống

Trong SQL chuẩn ISO và MySQL, các câu lệnh được chia làm 3 nhóm chính mà bạn bắt buộc phải biết khi bảo vệ đồ án:

1. DQL (Data Query Language)

Lệnh Truy Vấn & Rút Trích Dữ Liệu

Gồm duy nhất lệnh SELECT kết hợp cùng các mệnh đề FROM, WHERE, JOIN, GROUP BY, HAVING, ORDER BY, LIMIT. Dùng để xem, tìm kiếm, thống kê báo cáo mà không làm thay đổi dữ liệu gốc.

2. DML (Data Manipulation Language)

Lệnh Thao Tác & Biến Đổi Dữ Liệu

Gồm INSERT (Thêm mới), UPDATE (Sửa đổi), DELETE (Xóa dòng dữ liệu). Tác động trực tiếp vào nội dung các dòng trong bảng.

3. DDL (Data Definition Language)

Lệnh Định Nghĩa Cấu Trúc Bảng

Gồm CREATE (Tạo bảng), ALTER (Thêm/Sửa cột), DROP (Xóa sổ bảng), TRUNCATE (Làm sạch trắng bảng). Tác động vào cấu trúc khung sườn (schema.sql).

1. SELECT + WHERE

Truy Vấn Lọc Dữ Liệu Cơ Bản Có Điều Kiện

Ý nghĩa đời thường: Giống như bạn bảo lớp trưởng: "Hãy lấy cho tôi danh sách họ tên và email của các bạn sinh viên thuộc khóa D24 đang theo học bình thường". Mệnh đề WHERE đóng vai trò như bộ lọc trong Excel.

-- Lấy sinh viên Khóa D24 đang học, loại bỏ sinh viên đã thôi học hoặc tốt nghiệp
SELECT user_code AS ma_sv, name AS ho_ten, email, academic_status
FROM users
WHERE user_type = 'student'
AND cohort = 'D24'
AND academic_status = 'studying';
2. PHÉP JOIN (NỐI BẢNG)

Ghép Nhiều Sổ Sách Lại Với Nhau Bằng Khóa Ngoại

🔗 INNER JOIN (Chỉ lấy phần giao nhau):

Chỉ trả về các dòng mà cả 2 bảng đều có dữ liệu khớp nhau. Ví dụ: Lấy phiếu hỗ trợ và KTV đã tiếp nhận (những phiếu chưa ai nhận sẽ bị loại bỏ).

⬅️ LEFT JOIN (Lấy hết bên Trái):

Lấy 100% dòng ở bảng bên Trái, bảng bên Phải nếu chưa có dữ liệu thì tự động điền NULL. Rất quan trọng khi muốn thống kê: Liệt kê đủ tất cả 5 KTV kể cả KTV chưa được giao phiếu nào!

-- Ghép 3 bảng: Tickets + Users (Người gửi) + Classes (Lớp học)
SELECT t.ticket_code, t.title, u.name AS nguoi_gui, c.class_code
FROM tickets t
INNER JOIN users u ON t.requester_id = u.id
LEFT JOIN classes c ON t.class_id = c.id;
3. GROUP BY + HAVING

Gom Nhóm Thống Kê & Bộ Lọc Sau Gom Nhóm

⚠️ Điểm phân biệt "vàng" khi thầy/cô hỏi vấn đáp:
  • WHERE: Lọc từng dòng dữ liệu thô TRƯỚC khi hệ thống tiến hành gom nhóm.
  • HAVING: Lọc kết quả tính toán (như COUNT(), AVG(), SUM()) SAU khi đã gom nhóm xong. Không thể dùng WHERE để lọc hàm đếm!
-- Đếm số phiếu của từng KTV và chỉ lấy những KTV đang nhận từ 1 phiếu trở lên
SELECT u.name AS ten_ktv, COUNT(t.id) AS tong_so_phieu
FROM users u
LEFT JOIN tickets t ON t.assigned_to = u.id
WHERE u.role = 'agent'
GROUP BY u.id, u.name
HAVING tong_so_phieu >= 1
ORDER BY tong_so_phieu DESC;
4. DML (INSERT, UPDATE, DELETE)

Thao Tác Thêm Mới, Cập Nhật & Xóa Dữ Liệu

➕ INSERT INTO:

Thêm 1 bản ghi mới khi bạn bấm gửi phiếu báo hỏng hoặc import tài khoản đầu kỳ.

✏️ UPDATE ... SET:

Đổi trạng thái phiếu sang resolved, gán KTV, mở khóa tài khoản.

🗑️ DELETE FROM:

Xóa dữ liệu hết hạn (ví dụ mã token SSPR hết hạn sau 15 phút). Luôn luôn phải có WHERE!

-- Ví dụ UPDATE: KTV bấm hoàn thành phiếu sự cố
UPDATE tickets
SET status = 'resolved', resolved_at = NOW()
WHERE ticket_code = 'HD-2026-00002';
