1. ĐỊNH HƯỚNG PHẠM VI HỆ THỐNG & CƠ CHẾ AUTO-PRIORITY THÔNG MINH

1.1 Chuyển dịch chiến lược sang 100% Dịch vụ Trực tuyến (Pure Online Services)

Trong môi trường đại học hiện đại, các sự cố phần cứng offline (máy chiếu phòng học, thiết bị vật lý) phụ thuộc lớn vào việc mở khóa phòng, kiểm tra tại chỗ và mua sắm vật tư thay thế của Ban Cơ sở vật chất, không thể giải quyết tức thì và triệt để qua web. Do đó, hệ thống Helpdesk này được chuyển hướng chuyên biệt hóa 100% vào các dịch vụ và sự cố công nghệ thông tin trực tuyến của Trường Đại học Thủ Đô Hà Nội.

Lợi ích cốt lõi của mô hình Helpdesk Trực tuyến 100%:
  • Quy trình khép kín trực tuyến: Tiếp nhận → Tự động phân công chuyên môn / Tràn tải → Xử lý kỹ thuật từ xa → Nghiệm thu & Đánh giá CSAT trực tuyến.
  • Triệt tiêu rào cản địa lý & thời gian: KTV có thể xử lý sự cố từ xa cho sinh viên/giảng viên mọi lúc, kể cả trong các đợt học trực tuyến hay kỳ thi từ xa.
  • Cam kết SLA minh bạch: Đo lường chính xác thời gian phản hồi đầu tiên (First Response Time) và thời gian giải quyết thực tế (Resolution Time).

1.2 Giải quyết triệt để "Hội chứng Tất cả đều Khẩn cấp" bằng Cơ chế Auto-Priority Mapping

Vấn đề thực tế tại trường học: Nếu để sinh viên tự do chọn mức ưu tiên (Urgent, High, Med, Low), theo tâm lý chủ quan, 95% sinh viên sẽ chọn "Khẩn cấp" hoặc "Cao" để việc của mình được xử lý trước. Hậu quả là KTV bị quá tải ảo trong "bão phiếu đỏ", và các sự cố tê liệt hệ thống thật sự (sập mạng phòng thi, lỗi cổng đăng ký tín chỉ) bị chìm lấp.

Giải pháp thiết kế kiến trúc chuẩn mực (Áp dụng tiêu chuẩn ITIL v4):

  • Loại bỏ hoàn toàn ô chọn Priority khỏi form Sinh viên: Sinh viên chỉ cần chọn đúng Dịch vụ gặp lỗi, mô tả chi tiết và đính kèm ảnh chụp màn hình thông báo lỗi.
  • Tự động định mức ưu tiên theo Danh mục dịch vụ (Auto-Priority Mapping): Hệ thống tự động gán mức ưu tiên và hạn chót SLA khách quan theo danh mục.
  • Khóa cứng mức `URGENT` đối với Sinh viên thông thường: Mức URGENT chỉ được kích hoạt bởi Giảng viên (khi ảnh hưởng trực tiếp đến giờ lên lớp, thi cử) hoặc Admin Trung tâm CNTT (khi sự cố diện rộng).

💻 PHÂN HỆ 3: MODULE KỸ THUẬT VIÊN (AGENT WORKSPACE)

Không gian làm việc chuyên nghiệp dành cho đội ngũ KTV Trung tâm CNTT tiếp nhận, phân loại và xử lý sự cố từ xa:

A. Cơ chế Phân công theo Chuyên môn (Skill-based Routing) & Tiếp nhận Tràn tải (Overflow Queue)

Hệ thống gắn cứng mỗi KTV với 1 trong 5 nhóm chuyên môn chính dựa trên trường specialty_category_id trong CSDL:

  • KTV 1 (Chuyên môn SSO & Tài khoản): Tiếp nhận tự động yêu cầu mở khóa tài khoản, Guest Ticket của sinh viên bị khóa, lỗi đồng bộ danh tính.
  • KTV 2 (Chuyên môn Email & Cloud): Tiếp nhận các sự cố Microsoft 365, bản quyền Office, dung lượng OneDrive/SharePoint.
  • KTV 3 (Chuyên môn Cổng QLĐT): Tiếp nhận các lỗi cổng đăng ký tín chỉ, tra cứu điểm thi, cấp quyền nhập điểm cho giảng viên.
  • KTV 4 (Chuyên môn E-Learning Canvas/Teams): Tiếp nhận lỗi lớp học LMS, sự cố nộp bài tập lớn trực tuyến, xử lý lịch học nhầm ngày lễ.
  • KTV 5 (Chuyên môn Mạng & Wi-Fi): Tiếp nhận lỗi chứng thực mạng Thủ Đô (THUDO-UNI), sự cố mạng Ký túc xá, cấu hình VPN thư viện.
Cơ chế Tiếp nhận Tràn tải (Overflow Handling): Khi một KTV phụ trách chuyên môn bị bão phiếu (đạt ngưỡng tải tối đa active_tickets_count = 5), các phiếu phát sinh tiếp theo sẽ được thuật toán cân bằng tải động đẩy sang Hàng đợi Tràn tải (Overflow Queue) của các KTV còn lại đang trực có số lượng phiếu thấp nhất. 4.2 Thuật toán Điều phối Chuyên môn & San sẻ Tràn tải trong TicketService.php

// Phân công an toàn không tranh chấp: Ưu tiên KTV chuyên môn -> Tràn tải KTV ít việc nhất
public function autoAssignTicket(int $ticketId, int $categoryId, string $dueAt): bool 
{
    $this->pdo->beginTransaction();
    try {
        // 1. Tìm KTV chuyên môn trực ca và còn slot (< 5)
        $stmt = $this->pdo->prepare("
            SELECT id FROM users 
            WHERE role = 'agent' AND is_active = 1 AND is_on_duty = 1 
              AND specialty_category_id = :cat_id 
              AND active_tickets_count < max_capacity
            LIMIT 1 FOR UPDATE
        ");
        $stmt->execute([':cat_id' => $categoryId]);
        $targetAgent = $stmt->fetchColumn();

        // 2. KTV chuyên môn QUÁ TẢI (>= 5) hoặc NGHỈ TRỰC -> Kích hoạt Tràn tải (Overflow)
        if (!$targetAgent) {
            $stmt = $this->pdo->prepare("
                SELECT id FROM users 
                WHERE role = 'agent' AND is_active = 1 AND is_on_duty = 1 
                  AND active_tickets_count < max_capacity
                ORDER BY active_tickets_count ASC, id ASC
                LIMIT 1 FOR UPDATE
            ");
            $stmt->execute();
            $targetAgent = $stmt->fetchColumn();
        }

        // 3. Nếu TẤT CẢ KTV ĐỀU ĐẦY TẢI (25/25) -> Giữ ở hàng chờ 'new' để Admin điều phối
        if (!$targetAgent) {
            $this->pdo->commit();
            return false;
        }

        // 4. Tăng tải nguyên tử cho KTV được gán
        $stmt = $this->pdo->prepare("
            UPDATE users SET active_tickets_count = active_tickets_count + 1 
            WHERE id = :agent_id AND active_tickets_count < max_capacity
        ");
        $stmt->execute([':agent_id' => $targetAgent]);

        // 5. Cập nhật phiếu sang trạng thái in_progress
        $stmt = $this->pdo->prepare("
            UPDATE tickets 
            SET assigned_to = :agent_id, status = 'in_progress', due_at = :due_at 
            WHERE id = :ticket_id AND status = 'new'
        ");
        $stmt->execute([':agent_id' => $targetAgent, ':due_at' => $dueAt, ':ticket_id' => $ticketId]);

        $this->pdo->commit();
        return true;
    } catch (Exception $e) {
        if ($this->pdo->inTransaction()) $this->pdo->rollBack();
        throw $e;
    }
}

-- 2. BẢNG MỨC ĐỘ ƯU TIÊN (PRIORITIES)

    active_tickets_count TINYINT UNSIGNED NOT NULL DEFAULT 0, -- Bộ đếm nguyên tử
    is_on_duty TINYINT(1) NOT NULL DEFAULT 1, -- Ca trực: 1 (Đang trực), 0 (Nghỉ trực)

    failed_attempts TINYINT UNSIGNED NOT NULL DEFAULT 0,
    locked_until DATETIME NULL, -- Khóa mềm 30 phút sau 5 lần nhập sai

CREATE TABLE course_assignments (

CREATE TABLE password_resets (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id INT UNSIGNED NOT NULL,
    email VARCHAR(190) NOT NULL,

    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_token_lookup (token_hash, expires_at),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE

-- 10. BẢNG PHIẾU YÊU CẦU DỊCH VỤ SỐ (TICKETS)
-- Hỗ trợ: Gộp sự cố diện rộng, Guest Ticket, Liên kết Môn học & Lớp học
CREATE TABLE tickets (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    requester_id INT UNSIGNED NOT NULL,
    assigned_to INT UNSIGNED NULL,
    category_id INT UNSIGNED NOT NULL,
    priority_id INT UNSIGNED NOT NULL,
    parent_ticket_id INT UNSIGNED NULL, -- Gộp phiếu sự cố diện rộng LMS/QLĐT
    
    -- Định vị Môn học & Lớp học khi báo sự cố đào tạo
    class_id INT UNSIGNED NULL,
    course_id INT UNSIGNED NULL,
    
    is_guest_ticket TINYINT(1) NOT NULL DEFAULT 0,
    contact_email VARCHAR(190) NULL,
    lookup_pin VARCHAR(10) NULL,
    
    title VARCHAR(150) NOT NULL,
    description TEXT NOT NULL,
    system_affected VARCHAR(50) NOT NULL,
    attachment_path VARCHAR(255) NULL,
    
    status ENUM('new', 'in_progress', 'waiting_requester', 'resolved', 'closed') NOT NULL DEFAULT 'new',
    closed_reason ENUM('completed', 'auto_closed', 'duplicate', 'cancelled') NULL,
    
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    sla_started_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    triage_due_at DATETIME NOT NULL,
    due_at DATETIME NOT NULL,
    first_response_at DATETIME NULL,
    resolved_at DATETIME NULL,
    closed_at DATETIME NULL,
    reopen_count TINYINT UNSIGNED NOT NULL DEFAULT 0,
    
    ticket_code VARCHAR(30) GENERATED ALWAYS AS (
        CONCAT('HD-', YEAR(created_at), '-', LPAD(id, 5, '0'))
    ) STORED UNIQUE,

    INDEX idx_admin_queue (status, triage_due_at, due_at),
    INDEX idx_agent_work (assigned_to, status, due_at),
    INDEX idx_user_history (requester_id, created_at),
    INDEX idx_guest_lookup (ticket_code, lookup_pin),
    INDEX idx_ticket_academic (class_id, course_id),
    FOREIGN KEY (requester_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (assigned_to) REFERENCES users(id) ON DELETE SET NULL,
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE RESTRICT,
    FOREIGN KEY (priority_id) REFERENCES priorities(id) ON DELETE RESTRICT,
    FOREIGN KEY (parent_ticket_id) REFERENCES tickets(id) ON DELETE SET NULL,
    FOREIGN KEY (class_id) REFERENCES classes(id) ON DELETE SET NULL,
    FOREIGN KEY (course_id) REFERENCES courses(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 11. BẢNG PHẢN HỒI TRAO ĐỔI (TICKET_REPLIES)
CREATE TABLE ticket_replies (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    ticket_id INT UNSIGNED NOT NULL,
    user_id INT UNSIGNED NOT NULL,
    message TEXT NOT NULL,
    attachment_path VARCHAR(255) NULL,
    is_internal TINYINT(1) NOT NULL DEFAULT 0, -- 1: Private Note dành riêng cho KTV/Admin
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_ticket_replies (ticket_id, is_internal, created_at),
    FOREIGN KEY (ticket_id) REFERENCES tickets(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 12. BẢNG ĐÁNH GIÁ ĐỘ HÀI LÒNG CSAT (TICKET_RATINGS)
CREATE TABLE ticket_ratings (
    id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    ticket_id INT UNSIGNED NOT NULL UNIQUE, -- Quan hệ 1-1 với tickets
    user_id INT UNSIGNED NOT NULL,
    score TINYINT UNSIGNED NOT NULL, -- 1 đến 5 sao
    comment VARCHAR(500) NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (ticket_id) REFERENCES tickets(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT chk_ticket_ratings_score CHECK (score BETWEEN 1 AND 5)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
